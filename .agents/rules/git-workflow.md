# Git and Commit Standards

1. **Commit Message Format:**
   - Use Conventional Commits standard:
     - `feat: <description>` for new features
     - `fix: <description>` for bug fixes
     - `docs: <description>` for documentation changes
     - `refactor: <description>` for code restructuring
     - `chore: <description>` for tooling/maintenance
   - Keep messages concise, imperative, and in English.

2. **Branch Management:**
   - Keep commit units atomic and logically isolated.
   - Do not stage or commit build artifacts, local secret files, or temporary files.
